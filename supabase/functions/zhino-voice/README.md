# ZHINO — Supabase Edge Function «صدای فارسی دستیار»

این تابع، تنها مسیر مجاز اتصال فروشگاه به سرویس تبدیل متن به گفتار است. کلید سرویس
در **Secrets سوپابیس** می‌ماند و هرگز وارد مرورگر، بستهٔ نهایی یا این مخزن نمی‌شود.

```
مرورگر (فروشگاه)  ──POST {text}──►  zhino-voice (Deno)  ──►  Azure AI Speech
   بدون هیچ کلید                     AZURE_SPEECH_KEY اینجا     fa-IR-DilaraNeural
   ◄────── audio/mpeg (MP3) ──────
```

## چرا این تابع لازم شد؟

موتور صدای خودِ گوشی (Web Speech API) روی بیشتر دستگاه‌های اندروید **صدای فارسی
ندارد**. Chrome Android یا سکوت می‌کند یا کاربر را به «نصب صدای فارسی در تنظیمات»
می‌فرستد. با این تابع، فایل صوتی فارسی از سرور می‌آید و مثل هر صوت دیگری در صفحه
پخش می‌شود — **بدون هیچ نیازی به نصب صدا روی گوشی**.

تابع **هیچ جدولی را نمی‌خواند و هیچ چیزی نمی‌نویسد**؛ برخلاف `zhino-assistant` هیچ
`SELECT`ی نمی‌زند. فقط همان متنی را که فرانت‌اند فرستاده به صدا تبدیل می‌کند.

## ۱. ساخت منبع Speech در Azure

1. در [portal.azure.com](https://portal.azure.com) یک منبع **Speech service** بسازید.
2. لایهٔ **Free (F0)** را انتخاب کنید — ۵۰۰٬۰۰۰ کاراکتر رایگان در ماه، بدون انقضا.
3. از صفحهٔ **Keys and Endpoint** مقدار `KEY 1` و `Location/Region` را بردارید
   (مثلاً `westeurope`).

> صدای فارسی `fa-IR-DilaraNeural` (زن) و `fa-IR-FaridNeural` (مرد) در بیشتر
> نواحی موجودند. اگر ناحیه‌ای صدای فارسی نداشت، پاسخ `GET` این تابع
> `ready: false` برمی‌گرداند و سایت بی‌صدا به صدای خود دستگاه برمی‌گردد.

## ۲. تنظیم Secrets

```bash
supabase secrets set AZURE_SPEECH_KEY="<کلید Speech>" AZURE_SPEECH_REGION="westeurope"
# اختیاری:
supabase secrets set AZURE_SPEECH_VOICE="fa-IR-DilaraNeural"
supabase secrets set TTS_ALLOWED_ORIGINS="https://zheno.devs.surf,https://<user>.github.io"
```

| Secret | الزامی | توضیح |
| --- | --- | --- |
| `AZURE_SPEECH_KEY` | ✅ | کلید Speech. فقط سمت سرور؛ هرگز در `VITE_*` نگذارید. |
| `AZURE_SPEECH_REGION` | ✅ | ناحیهٔ منبع، مثل `westeurope` یا `uaenorth`. |
| `AZURE_SPEECH_VOICE` | — | پیش‌فرض `fa-IR-DilaraNeural` (زن). برای صدای مرد: `fa-IR-FaridNeural`. |
| `TTS_ALLOWED_ORIGINS` | — | پیش‌فرض `*`؛ در محیط واقعی دامنه‌های خودتان را بگذارید. |

اگر `TTS_ALLOWED_ORIGINS` تنظیم نشده باشد، مقدار `ALLOWED_ORIGINS` (همان Secret
دستیار) هم پذیرفته می‌شود.

## ۳. استقرار

```bash
supabase functions deploy zhino-voice
```

- `verify_jwt` پیش‌فرض روشن است؛ فرانت‌اند هدر `Authorization: Bearer <publishable key>`
  را می‌فرستد (همان کلید عمومی پروژه).
- تابع هیچ نوشتنی در دیتابیس ندارد و به هیچ جدولی دست نمی‌زند.

## ۴. تنظیم فرانت‌اند

کاری لازم نیست: اگر `VITE_SUPABASE_URL` و کلید عمومی پروژه تنظیم شده باشند،
فروشگاه خودش این تابع را روی `<VITE_SUPABASE_URL>/functions/v1/zhino-voice`
صدا می‌زند. اگر Backend اختصاصی خودتان را دارید:

```bash
VITE_VOICE_API_URL=https://api.example.com/voice
```

اگر هیچ‌کدام تنظیم نشده باشد، خواندن پاسخ **دقیقاً مثل قبل** با صدای خود دستگاه
انجام می‌شود.

## ۵. قرارداد API

| متد | پاسخ | کاربرد |
| --- | --- | --- |
| `GET` | `{ ok, configured, ready, voice, locale, format }` | بررسی آماده‌بودن سرویس و موجودبودن صدای فارسی در آن ناحیه |
| `POST` | `audio/mpeg` (بدنهٔ باینری MP3) | ساخت صدا برای یک متن |

بدنهٔ `POST`:

```json
{ "text": "ژله توت فرنگی ۲۰۰٬۰۰۰ تومان است." }
```

خطاها (همه JSON): `400` متن خالی/نامعتبر، `403` دامنهٔ ناشناس، `405` متد نادرست،
`413` بدنهٔ بزرگ، `429` سهمیهٔ درخواست، `501` پیکربندی‌نشده، `502` سرویس پاسخ نداد.
فرانت‌اند در همهٔ این حالت‌ها **بی‌صدا** به صدای خود دستگاه برمی‌گردد و اگر آن هم
نبود، همان پیام کوتاه قبلی را نشان می‌دهد.

## ۶. هزینه و محدودیت

| مورد | مقدار |
| --- | --- |
| رایگان (Azure F0) | ۵۰۰٬۰۰۰ کاراکتر در ماه، بدون انقضا (≈ ۱۰ ساعت گفتار) |
| بعد از سهمیهٔ رایگان | حدود ۱۶ دلار به‌ازای هر ۱ میلیون کاراکتر |
| سقف متن هر درخواست | ۱۲۰۰ کاراکتر (`MAX_TEXT_CHARS`) |
| سقف بدنهٔ درخواست | ۸ کیلوبایت (`MAX_BODY_BYTES`) |
| سهمیهٔ ضدسوءاستفاده | ۴۰ درخواست در ۵ دقیقه برای هر IP در هر نمونه |
| مهلت سرویس | ۲۰ ثانیه |

یک پاسخ معمولی دستیار حدود ۲۰۰ کاراکتر است، یعنی سهمیهٔ رایگان تقریباً
**۲٬۵۰۰ پاسخ در ماه** را پوشش می‌دهد. علاوه بر این، مرورگر صدای هر پاسخ را در
حافظه نگه می‌دارد، پس «پخش مجدد» همان پاسخ هیچ کاراکتر تازه‌ای مصرف نمی‌کند.

## ۷. نکات امنیتی

- کلید سرویس هرگز در `src/`، `VITE_*`، GitHub Secretsِ فرانت‌اند یا بستهٔ نهایی نمی‌آید.
- پاسخ تابع هیچ‌وقت کلید یا خطای خام سرویس‌دهنده را برنمی‌گرداند (جزئیات فقط در لاگ سرور).
- متن ورودی پیش از رفتن به SSML کاملاً XML-escape می‌شود؛ متن پاسخ نمی‌تواند
  تگ یا دستور تازه بسازد (همان اصل «دادهٔ مرجع، نه دستور»).
- تابع به هیچ جدولی دسترسی ندارد: نه `orders`، نه `products` — هیچ `SELECT`ی نمی‌زند.
- فقط «متن پاسخ دستیار» فرستاده می‌شود؛ هرگز سؤال کاربر، نام، نشانی یا سبد خرید.
- `TTS_ALLOWED_ORIGINS` را در محیط واقعی روی دامنه‌های خودتان بگذارید
  (پیش‌فرض `*` فقط برای راه‌اندازی سریع مناسب است).
- صدای تولیدشده فقط در حافظهٔ همان صفحه (tab) نگه داشته می‌شود و با ترک صفحه
  پاک می‌شود؛ نه در دیتابیس ذخیره می‌شود، نه روی دیسک.
