# اجرای امن مهاجرتِ گالری تصاویر محصولات («تصاویر محصولات»)

فایل نهایی و تأییدشدهٔ مهاجرت:

```
supabase/migrations/20260919000000_product_images.sql
```

این فایل هر سه چیز لازم برای کارکرد گالری را می‌سازد یا — اگر از قبل
بخشی وجود داشته — **ترمیم** می‌کند:

| چه چیزی | نقش |
|---|---|
| جدول `public.product_images` + RLS | ردیف هر تصویر؛ نوشتن فقط برای نقش `admin` |
| تابع `public.set_primary_product_image(uuid)` | انتخاب اتمی «تصویر اصلی» + ثبت نشانی در `products.image_url` |
| سطل Storage به نام `product-images` + ۴ policy | نگهداری فایل‌ها؛ نوشتن/حذف فقط برای مدیر |

**این مهاجرت کاملاً idempotent (قابل اجرای مجدد بدون خطا) است.** روی
PostgreSQL واقعی تست شده: اجرای دوم و سوم — حتی روی پروژه‌ای که جدول را
دارد اما سطل را ندارد — بدون خطا تمام می‌شود، قطعهٔ گمشده را می‌سازد و
به هیچ دادهٔ موجود (محصول‌ها، ردیف‌های گالری، `products.image_url`)
دست نمی‌زند. ثبت تصویرهای فایلِ خود سایت هم فقط برای محصول‌هایی انجام
می‌شود که هنوز هیچ ردیفی در گالری ندارند؛ محصول‌هایی که پنل مدیریت‌شان
کرده حذف/ثبت مجدد نمی‌شوند.

## روش ۱ — SQL Editor ِداشبورد (توصیه‌شده؛ پروژه‌هایی که چند فایل را دستی اعمال می‌کنند)

۱. Supabase Dashboard → پروژهٔ خود → **SQL Editor** → **New query**.
۲. کل محتوای `supabase/migrations/20260919000000_product_images.sql` را
   کپی و در ویرایشگر بچسبانید.
۳. **Run** کنید. اگر از قبل بخشی اعمال شده باشد، اجرای مجدد بدون خطا و
   بدون تغییر در داده‌ها تمام می‌شود؛ چیزی خراب نمی‌شود.
۴. برای اطمینان، کوئری‌های بخش ۸ و ۹ فایل `supabase/verify.sql` را اجرا
   کنید؛ انتظار می‌رود:
   - ردیف سطل: `product-images`, `public = true`, سقف `8388608` بایت
   - ۴ policy به نام‌های `product_images_storage_read / _insert / _update / _delete`
   - `image_rows = 22` (برای هر محصولِ دارای تصویر یک ردیف `legacy`)
   - `products_with_two_primaries = 0`

## روش ۲ — Supabase CLI (پروژه‌هایی که با `db push` مدیریت می‌شوند)

```bash
supabase link --project-ref <REF-پروژه>
supabase db push
```

توجه: `db push` فقط مهاجرت‌هایِ *اعمال‌نشده* را اجرا می‌کند. اگر نسخهٔ
این فایل قبلاً ثبت شده باشد اما پروژه در وضعیت ناقص است (مثلاً فقط سطل
گم شده)، برای ترمیم از روش ۱ استفاده کنید.

## بعد از اجرا

۱. در پنل مدیریت → «تصاویر محصولات» دکمهٔ **به‌روزرسانی** را بزنید؛ بنر
   خطای «فضای ذخیره‌سازی … ساخته نشده» دیگر ظاهر نمی‌شود.
۲. همان آپلودی که خطا گرفته بود را دوباره انجام دهید — تصویر در سطل
   `product-images` ذخیره و در گالری ثبت می‌شود.

## آنچه این مهاجرت هرگز انجام نمی‌دهد

- هیچ ردیفی از جداول موجود (محصولات، سفارش‌ها، موجودی …) را به‌روز یا حذف نمی‌کند.
- هیچ فایلی از `public/images/` را جابه‌جا یا حذف نمی‌کند.
- `products.image_url` — تنها فیلدی که فروشگاه می‌خواند — را بازنویسی
  نمی‌کند؛ بازنویسی آن فقط وقتی و فقط در تراکنشِ انتخاب «تصویر اصلی»
  در پنل اتفاق می‌افتد.
- هیچ credential یا secret‌ای در فایل نیست؛ همهٔ دسترسی‌ها همان مدل RLS
  موجود پروژه است (نوشتن فقط برای حساب با `app_metadata.role = "admin"`).
